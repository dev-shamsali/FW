# Rhea.js v0.1.0-alpha.3

**Access and refresh tokens, morgan, and a stronger default security posture.**

> Alpha software. The API can change between alpha releases. It is not production-ready and has had no independent security review. See `SECURITY_AUDIT.md` for what was tested and what is still open.

## Breaking change

A `POST`, `PUT`, `PATCH` or `DELETE` with a body that is not JSON now gets `415 UNSUPPORTED_MEDIA_TYPE`, instead of reaching your handler empty. Clients that send `Content-Type: application/json` are not affected. If you accept forms or uploads, create the app with `requireJson: false`.

## What is new since 0.1.0-alpha.2

- **A git repository from the first second.** `npx create-rhea my-api` now runs `git init`, and makes the first commit on `main` after the install (so the lockfile is in it). Your `.env` is never committed. Skipped inside an existing repository or with `--no-git`.
- **Put it on GitHub from `create`.** If the GitHub CLI is installed and signed in, `create` offers to create the repository and push (default No, then Private or Public). Flags: `--github-private`, `--github`, `--no-github`. Nothing is sent anywhere without your yes or a flag.
- **A cleaner project.** No more empty `src/middleware`, `src/utils`, `tests/unit` and `tests/e2e` folders with `.gitkeep` files.

- **Refresh tokens.** `npx create-rhea my-api --auth` now gives you `POST /api/auth/refresh`, `/logout` and `/logout-all` next to register, login and `/me`. The access token lives 15 minutes. The refresh token is random, stored only as a hash, valid 7 days unused and 30 days in total, and replaced on every use.
- **Reuse detection.** If an old refresh token comes back, the whole session is revoked (`401 REFRESH_REUSED`). Two parallel requests with the same token are not theft: exactly one wins, the other gets `REFRESH_CONFLICT` and can retry.
- **Cookie mode for browser apps.** `AUTH_REFRESH_COOKIE=true` keeps the refresh token in an `httpOnly`, `SameSite=Strict`, `Secure` cookie that page scripts cannot read, with a CSRF check on the `Origin` header.
- **Account lockout.** Five wrong passwords lock the account for 15 minutes (`429 ACCOUNT_LOCKED` with `Retry-After`). Common passwords are rejected at registration.
- **Morgan.** In development you see one short colored line per request. Production keeps the structured JSON log with request IDs. Query strings, cookies and most headers are never printed.
- **More defaults.** `Permissions-Policy` header, `rejectOperatorKeys` to block MongoDB `$ne`/`$gt` style bodies (on in generated MongoDB projects), `Cache-Control: no-store` on every token response, and a one-time warning when `X-Forwarded-For` arrives while `trustProxy` is off.
- **Library pieces** for your own apps in `@rheajs/auth`: `createRefreshTokens`, `createMemoryRefreshStore`, cookie helpers, `createLockout`, `isCommonPassword`.

## Upgrading

- Projects generated with alpha.2 keep working. They do not get refresh tokens until you copy the new `src/modules/auth/` and `src/config/auth` from a fresh `--auth` project. The users table (MySQL) or collection (MongoDB) is upgraded on first start.
- New projects: `npx create-rhea my-api --auth --db mysql` (or `mongodb`).

## Verified before release

- 74 end-to-end checks over HTTP against real MongoDB 7 and MySQL 8.4, for body mode and cookie mode, including a burst of 10 parallel refreshes with one token (exactly one succeeds) and upgrading an alpha.2 database.
- Unit tests for every new function; the CI matrix covers Linux, macOS and Windows on Node.js 20, 22 and 24.

## Known limitations

- No server-side sessions, OAuth/OIDC, MFA, password reset or change-password yet. An access token cannot be revoked before it expires, but logout stops it from being renewed.
- A lock answer reveals that an account exists (after five failures), and anyone who knows an email can lock that account for 15 minutes by guessing.
- Rate-limit counters are per process unless you pass a shared store.
- HS256 only. No independent security review.
