# Rhea.js 1.0.1

Bug fixes from building a real browser app (Next.js) against a generated API in cookie mode.

- **Fixed:** projects generated with `--auth` now enable CORS credentials when `AUTH_REFRESH_COOKIE=true`. Without it, browsers blocked every call that sent the refresh cookie.
- **Fixed:** a refresh refused as `CSRF_ORIGIN` no longer clears the real refresh cookie.
- **Added:** `cors.exposedHeaders` (default `["Retry-After"]`), so a login page can show how long a lockout lasts.
- **Docs:** clearer authentication guide (cookie mode, rate-limit codes, token clock tolerance, React strict mode).

Existing projects: add `credentials: env.AUTH_REFRESH_COOKIE` to the `cors` option in `src/app.ts` and update `@rheajs/core`, `@rheajs/auth` and `@rheajs/cli` to 1.0.1.
