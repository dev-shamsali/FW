# Rhea.js v0.1.0-alpha.2

**Authentication, a shared rate limit and a security pass.** New package `@rheajs/auth`, optional login in generated projects, and fixes from a security self-audit.

> Alpha software. The API can change between alpha releases. It is not production-ready and has had no independent security review. The self-audit is published in `SECURITY_AUDIT.md`, with what was fixed and what is still open.

## What is new since 0.1.0-alpha.1

- **`@rheajs/auth`** (new package): scrypt password hashing, HS256 JWT access tokens, and `authenticate`, `optionalAuth` and `requireRole` route guards.
- **Authentication in new projects.** When you pick MongoDB or MySQL, `npx create-rhea` asks "Add authentication?" (`--auth` / `--no-auth`). You get `POST /api/auth/register`, `POST /api/auth/login` and `GET /api/auth/me`, users stored in your database, a generated `JWT_SECRET`, and a test that needs no database.
- **Shared rate limiting.** `rateLimit` accepts `store`, `keyGenerator` and `skip`; `rateLimiter()` protects a single route; `redisRateLimitStore()` shares counters across instances.
- **Safer process behaviour.** An uncaught exception or unhandled rejection logs, shuts down gracefully and exits with code 1. Server keep-alive, header and request timeouts have load-balancer-friendly defaults.
- **Security fixes.** The prototype-pollution guard can no longer be bypassed by nesting deeper than 32 levels (such bodies are now rejected). Log redaction reaches nested values and more key names. `rhea generate` refuses Windows device names.
- **Measured, not claimed.** `BENCHMARKS.md` has a load test and a 180 s soak test with the exact method and caveats. Rhea.js is slower than bare Express on a trivial route (about 60% of its throughput on the test machine) because of the checks it runs on every request.

## Install

```bash
npx create-rhea my-api
```

Requires Node.js 20.19 or newer. Add authentication to an existing project with `npm install @rheajs/auth` and the [authentication guide](https://rhea.devcodehub.cloud/docs/authentication/).

## Verified before release

- 135 unit tests and the full end-to-end suite pass, including pseudo-terminal prompt tests and real MongoDB 7, MySQL 8.4 and Redis 7 containers.
- Both new auth flavours (TypeScript ESM with MySQL, JavaScript CommonJS with MongoDB) were registered, logged in and queried against real databases.
- The CI matrix covers Linux, macOS and Windows on Node.js 20, 22 and 24.

## Known limitations

- No refresh tokens, sessions, OAuth/OIDC, MFA, password reset or account lockout. Access tokens cannot be revoked before they expire.
- HS256 only.
- Each password hash in progress needs about 128 MiB of memory. Give containers at least 1 GiB when using auth.
- No ORM or query layer.
- Rate-limit counters are per process unless you pass a shared store.
- `npm audit` flags dev-only Vitest advisories in generated projects; the production audit is clean. See `docs/troubleshooting`.
- `docker compose` files are checked structurally, not run with Compose.
